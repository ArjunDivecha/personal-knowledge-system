## 1. Assessment

This is one of the more mature repos in the ecosystem, and the maturity is real, not
cosmetic. The git history since January is a long march of reliability work — data-loss
prevention in Dream (`Phase 0+1: stop data loss`), outcome-gated Dream apply, judge-queue
routing, nightly orchestrator with locking/ledger/resume, SDK auth+billing fallback — and
it shows the discipline the global CLAUDE.md preaches (incremental writes, no-fake-zero,
explicit failure). The test surface is substantial: ~40 files under `tests/python/`, a
Worker vitest suite, and an 8-axis retrieval probe suite. This is not a prototype.

The honest weaknesses are structural, not local:

- **Retrieval quality is measured but not *enforced*.** `scripts/run_eval.py` (added
  today) scores 8 axes and has a `--compare OLD NEW` mode (`run_eval.py:110`), but that
  mode is descriptive — it prints deltas and never returns nonzero. No baseline report is
  committed (`git ls-files | grep baseline` is empty), and `scripts/reports/` is gitignored,
  so there is no durable "last known good". The system that decides what Arjun's agents
  recall can therefore degrade silently. This is the single highest-leverage gap and the P0.

- **Two MCP servers with divergent embedding dimensions.** `cloudflare-mcp/mcp-server/`
  (production) and root `mcp-server/` (legacy) both exist; the legacy one embeds at
  `text-embedding-3-small`@1536 while production + Python use `text-embedding-3-large`@3072
  (`AGENTS.md:135-139`). A stray deploy of the legacy server against the live Vector index
  would write incompatible vectors — a latent foot-gun kept alive only by discipline.

- **Env loading is fragile and per-subsystem.** The in-flight uncommitted change to
  `ingestion/core/config.py` (`load_dotenv(..., override=True)` to stop a repo-level
  provider key shadowing the OpenAI embedding key) is a fix for exactly the kind of silent
  cross-repo bug that is hard to notice and easy to reintroduce. Env resolution differs
  between `distillation/config.py` and `ingestion/core/config.py`.

- **Destructive full-refresh path.** `distillation/run.py` clears stored entries before
  re-writing (`AGENTS.md:89`). It is correctly flagged in docs, but a destructive path with
  no dry-run guard rail one flag away from live memory deserves a hard confirmation gate.

Correctness risk is concentrated in the Dream/forgetting path (irreversible archival) and
in retrieval ranking (silent quality drift). Both are guarded by tests today; the gap is
that nothing turns "quality didn't regress" into a blocking command.

## 2. Prioritized improvements

### P0 — Commit a retrieval-quality baseline + a regression gate
**What/why.** Turn the descriptive `--compare` into a deterministic gate and commit a
baseline, so retrieval quality cannot silently regress. Evidence: `run_eval.py:110`
(`--compare` prints only); `scripts/reports/` gitignored; no committed baseline.
**Bet.** *If* a fresh eval report is compared to the committed baseline with the gate on,
*then* it exits nonzero on any enabled-probe pass→fail flip or any axis metric dropping
beyond tolerance, and exits 0 otherwise; *observable:* `--fail-on-regression` exit code,
deterministic, offline for the compare step.
**Invariants.** Self-compare exits 0; a degraded fixture forces nonzero; compare path is
network-free; UNMEASURED (null) axes are skipped, not scored as 0.
**Gate intents.** Offline unit test over synthetic old/new reports asserting exit codes;
`git diff` subset-of-scope check; one permissioned network run vs staging.
**Effort.** ~0.5 day. **This is authored as a full contract in §3.**

### P1 — Quarantine or dimension-guard the legacy MCP server
**What/why.** Prevent an incompatible-embedding deploy. Evidence: `AGENTS.md:135-139`.
**Bet.** *If* a deploy is attempted from `mcp-server/`, *then* it fails fast (or the server
refuses to write vectors whose dimension ≠ the index dimension); *observable:* a preflight
assertion in the legacy build/deploy path exits nonzero on dimension mismatch, or the
directory is moved under `legacy/` and its deploy script removed.
**Invariants.** No code path writes 1536-dim vectors to the 3072-dim production index; the
production Worker is unaffected.
**Gate intents.** A test asserting the embedding dimension constant matches the Vector index
dimension; grep-gate that no live deploy target points at the legacy dir.
**Effort.** ~0.5 day (guard) or ~1h (quarantine move, needs Arjun's kill decision).

### P1 — Hard confirmation gate on the destructive distillation refresh
**What/why.** `distillation/run.py` clears entries before rewrite (`AGENTS.md:89`); a
mis-run wipes canonical memory. Bloomberg-style "precious data" rule applies to memory too.
**Bet.** *If* `run.py` is invoked without an explicit `--force-clear` (or an interactive
confirmation), *then* it refuses to clear and exits nonzero; *observable:* running it
without the flag leaves entry counts unchanged and returns nonzero.
**Invariants.** No clear without explicit opt-in; a timestamped backup is taken before any
clear (mirrors the repo's `backup_memory.py` discipline).
**Gate intents.** Unit test with a mocked store asserting no delete calls without the flag;
assert a backup artifact is produced when the flag is set.
**Effort.** ~0.5 day.

### P2 — Unify env loading behind one resolver
**What/why.** Two `config.py` files resolve `.env` differently; the `override=True` fix is a
symptom. Evidence: uncommitted `ingestion/core/config.py` diff.
**Bet.** *If* both subsystems load env through one shared resolver with explicit precedence,
*then* an unrelated repo-level key can never shadow a subsystem key; *observable:* a test
sets a conflicting repo-level var and asserts the subsystem key still wins.
**Invariants.** Documented precedence order; both subsystems import the same resolver.
**Gate intents.** A parametrized test over the precedence matrix.
**Effort.** ~1 day (touches two subsystems — verify no ingestion behavior change).

### P2 — Make eval `--base-url` explicit in any automated context
**What/why.** `run_eval.py:82` defaults to production (`https://mcp.dancing-ganesh.com`); an
automated baseline run against prod mutates `access_count` on top-5 results (flagged in the
header, but still a side effect). Prefer staging by default in CI.
**Bet.** *If* the eval runs in an automated/gated context, *then* it targets staging unless
prod is explicitly requested; *observable:* the gate command names a non-prod base-url.
**Effort.** ~1h.

## Context

This repository is the Personal Knowledge System (PKS): a Cloudflare Worker MCP
server (`cloudflare-mcp/mcp-server/src/index.ts`) that serves retrieval over
memories stored in Upstash Redis + Vector, fed by Python ingestion pipelines.
Repo root on the author's machine:
`/Users/arjundivecha/Dropbox/AAA Backup/A Working/Memory/knowledge-system`.

`scripts/run_eval.py` (added 2026-07-06) is a retrieval-mode eval runner. It
loads a probe suite from `tests/probes/*.json` (one file per axis: recall,
project, explicit_save, exact_lexical, stale_fact, supersession, negative,
paraphrase), issues each enabled probe's query against the MCP `search` tool
(read-only), scores per-axis metrics (recall_at_k, stale_leak_rate,
supersession_accuracy, negative_precision, paraphrase_consistency), and writes a
timestamped JSON report to `scripts/reports/eval_baseline_<UTC>.json`. That
reports directory is gitignored, so reports are not durable artifacts.

The runner already has a `--compare OLD NEW` mode that prints per-axis metric
deltas and per-probe pass/fail flips, but it is descriptive only: it never
returns a nonzero exit on regression, and no baseline report is committed to the
repo. Consequently retrieval quality can silently degrade — nothing enforces
"no worse than last known good". "UNMEASURED" means an axis had zero enabled
probes and its metric is reported as null (the repo forbids faking a zero).

The task: add a committed baseline report at `tests/baselines/retrieval_baseline.json`
and a `--fail-on-regression` gate to the compare path so the comparison becomes
a deterministic pass/fail check, plus offline unit coverage. This freezes the
judgment of "what counts as a retrieval regression" into an external command
that a cheaper coding model or CI can enforce without re-deriving it. Do not
change retrieval behavior in the Worker; this contract only adds measurement and
a gate. `tests/probes/**` is `scope.out`: reuse the existing probes, do not
author new ones here.

## Build Loop vs Product Loop

The build loop is fully machine-checkable and offline. The coding model resolves
the TODO gate commands into repo-native tests (`tests/python/test_run_eval_compare.py`
run via `make test-python-checker`, i.e. `unittest discover -s tests/python`) and
a CLI invocation of `run_eval.py --compare ... --fail-on-regression` over local
JSON fixtures. Gates G1-G4 must exit 0 with no network access; they prove that
the regression gate fires on a degraded report, stays silent on an unchanged one,
skips UNMEASURED axes, and touches only in-scope files. These build-loop gates
prove the contract, not the product bet.

The product loop is the real bet: that this gate, run against fresh production
retrieval, actually catches quality regressions before they reach daily use.
That can only be judged by running G5 (the permissioned, network gate) against
the live MCP over time and observing that real regressions are caught and false
alarms are rare. The coding model may not claim the product bet is satisfied
merely because the build-loop gates pass: a gate that is green on synthetic
fixtures proves the comparison logic works, not that retrieval quality is
actually healthy or that the thresholds are well-calibrated against real drift.
